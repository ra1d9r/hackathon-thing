# Учебное наполнение — как редактировать

Всё, что здесь лежит, — **данные, а не код**. Правьте JSON-файлы любым текстовым
редактором. Через приложение это не редактируется и не должно.

> **Двенадцать файлов сейчас содержат заготовки** — временное содержимое,
> на котором система работает, но учить по нему нечему. Что именно и в каком
> порядке заменять: [`PLACEHOLDERS.md`](PLACEHOLDERS.md).
> Актуальный список печатает `npm run content -- --check`.

## Рабочий цикл

```bash
cd backend
npm run content -- --check    # проверить, ничего не записывая
npm run content               # записать в базу
```

Сначала всегда `--check`. Он делает настоящую загрузку в транзакции и откатывает её,
поэтому ловит не только опечатки в структуре, но и ссылки на несуществующие темы.
Если что-то не так — покажет файл и конкретное поле, а база останется нетронутой.

Повторный запуск не создаёт дубликатов: записи привязаны к полю `code`.
Изменили текст вопроса — обновится существующий; добавили новый блок с новым `code` —
добавится новая запись.

> **Не меняйте `code` у того, что уже загружено.** Это создаст новую запись, а старая
> останется висеть. Если нужно переименовать — сначала удалите старую (см. в конце).

## Где что лежит

| Файл | Что задаёт |
|---|---|
| `subjects.json` | список предметов |
| `topics/<предмет>.json` | темы предмета, вес на экзамене, порядок изучения |
| `exams.json` | чертежи экзаменов: баллы по секциям и какие предметы можно выбрать |
| `questions/diagnostic.json` | банк вопросов диагностического теста |
| `questions/mock-ent.json`, `mock-nis.json` | пробники экзаменов |
| `lessons.json` | учебные материалы и планы уроков |

## Вопрос диагностики

Откройте `questions/diagnostic.json`, найдите массив `"questions"` и добавьте блок.
Порядок в файле не важен — тест собирается под каждого ученика отдельно.

### С выбором одного ответа

```json
{
  "code": "math.trig.cos_pi4",
  "kind": "mcq_single",
  "topic_code": "math.trigonometry",
  "grade": 11,
  "difficulty": 2,
  "prompt_md": "Вычислите значение cos(π/4).",
  "options": [
    { "id": "a", "text_md": "0" },
    { "id": "b", "text_md": "1/2" },
    { "id": "c", "text_md": "√2/2" },
    { "id": "d", "text_md": "√3/2" },
    { "id": "e", "text_md": "1" }
  ],
  "answer_key": { "correct": ["c"] },
  "explanation_md": "π/4 соответствует 45°, косинус этого угла равен √2/2.",
  "points": 1
}
```

Поля по порядку:

- **`code`** — ваш уникальный идентификатор. Любая строка из строчных латинских букв,
  цифр, точек, дефисов и подчёркиваний. Удобно держать схему `предмет.тема.суть`.
- **`kind`** — `mcq_single`, `mcq_multi`, `free_text` или `numeric`.
- **`topic_code`** — код темы из `topics/<предмет>.json`. Должен существовать,
  иначе `--check` укажет на ошибку. Предмет подставится сам по теме.
- **`grade`** — класс, 7–12. Вопрос попадёт только тем, кому подходит.
- **`difficulty`** — 1–5, на ваше усмотрение.
- **`prompt_md`** — текст вопроса. Разметка — ограниченный набор, см. в конце.
- **`options`** — от 2 до 8 вариантов. `id` короткий (до 4 символов), удобно `a`…`e`.
- **`answer_key`** — эталон. Клиенту не отдаётся никогда.
- **`explanation_md`** — разбор, показывается после ответа. Можно не заполнять (`null`).
- **`points`** — сколько баллов стоит вопрос.

### С несколькими верными ответами

То же самое, но `kind` — `mcq_multi`, а в `correct` перечислены все верные:

```json
{
  "code": "phys.optics.wave_properties",
  "kind": "mcq_multi",
  "topic_code": "phys.optics",
  "grade": 11,
  "difficulty": 4,
  "prompt_md": "Отметьте все явления, подтверждающие волновую природу света.",
  "options": [
    { "id": "a", "text_md": "Интерференция" },
    { "id": "b", "text_md": "Дифракция" },
    { "id": "c", "text_md": "Фотоэффект" },
    { "id": "d", "text_md": "Поляризация" },
    { "id": "e", "text_md": "Эффект Комптона" }
  ],
  "answer_key": { "correct": ["a", "b", "d"] },
  "explanation_md": "Фотоэффект и эффект Комптона — наоборот, доводы в пользу квантовой природы.",
  "points": 2
}
```

### Со свободным ответом

Вариантов нет, зато **обязательны критерии оценивания** — по ним ИИ выставляет балл.
Без них проверка была бы произвольной, и загрузчик такой вопрос не примет.

```json
{
  "code": "math.free.quadratic_roots",
  "kind": "free_text",
  "topic_code": "math.polynomials",
  "grade": 11,
  "difficulty": 3,
  "prompt_md": "Решите уравнение x² − 5x + 6 = 0 и объясните, каким способом вы это сделали.",
  "options": null,
  "answer_key": {
    "expected_points": [
      "получены корни 2 и 3",
      "назван способ: дискриминант или теорема Виета",
      "показан ход решения"
    ]
  },
  "rubric_md": "Полный балл (3): найдены оба корня, назван способ, показан ход решения.\nЧастичный (2): корни верные, объяснения нет.\nЧастичный (1): найден один корень.\nНоль: корни неверны и решения нет.",
  "explanation_md": "D = 25 − 24 = 1, корни x = (5 ± 1)/2, то есть 2 и 3.",
  "points": 3
}
```

`expected_points` — что должно прозвучать в ответе; `rubric_md` — как распределяются баллы.
Заполняйте оба: первое ИИ использует как ориентир, второе — как шкалу.

### С числовым ответом

```json
{
  "code": "phys.kin.free_fall_time",
  "kind": "numeric",
  "topic_code": "phys.kinematics",
  "grade": 11,
  "difficulty": 2,
  "prompt_md": "Тело падает без начальной скорости с высоты 45 м. За сколько секунд оно достигнет земли? (g = 10 м/с²)",
  "options": null,
  "answer_key": { "value": 3, "tolerance": 0.1 },
  "explanation_md": "h = gt²/2, отсюда t = √(2h/g) = √9 = 3 с.",
  "points": 1
}
```

`tolerance` — допустимое отклонение. Проверяется без участия ИИ.

## Тема

Темы лежат по файлу на предмет: `topics/math.json`, `topics/physics.json` и так далее.

```json
{
  "code": "math.matrices",
  "title_ru": "Матрицы и определители",
  "grade_min": 10,
  "grade_max": 11,
  "exam_weight": 1.2,
  "sort_order": 130,
  "prerequisites": ["math.vectors"]
}
```

- **`exam_weight`** — насколько тема весома на экзамене. 1.0 — обычная, выше — встречается
  чаще. Влияет на приоритет темы в списке проблемных и на средний процент по предмету.
- **`sort_order`** — порядок показа. Оставляйте промежутки (10, 20, 30), чтобы можно
  было вставлять между.
- **`prerequisites`** — коды тем, без которых эту не понять. Тема не откроется в дорожной
  карте, пока они не пройдены. Можно не указывать.

Заменяя заготовку целиком, уберите строку `"placeholder": true` и блок `"_ЗАГОТОВКА"` —
тогда файл перестанет попадать в список незаполненного.

## Урок и материал

`lessons.json`. Один блок задаёт сразу и материал для чтения, и план урока.

```json
{
  "code": "lesson.math.logarithms.basics",
  "topic_code": "math.logarithms",
  "title": "Логарифмы: основы",
  "grade_min": 10,
  "grade_max": 11,
  "outline": [
    { "step": 1, "kind": "intro",    "title": "Зачем нужны логарифмы", "duration_min": 3 },
    { "step": 2, "kind": "reading",  "title": "Определение и свойства", "duration_min": 10 },
    { "step": 3, "kind": "quiz",     "title": "Проверка знаний",        "duration_min": 7 }
  ],
  "material": {
    "title": "Логарифмы: основы",
    "summary": "Определение логарифма, основные свойства, переход к другому основанию.",
    "est_read_minutes": 10,
    "body_md": "# Логарифмы\n\nЛогарифм отвечает на вопрос: **в какую степень возвести основание**, чтобы получить число.\n\n> log₂ 8 = 3, потому что 2³ = 8\n\n## Свойства\n\n- log(ab) = log a + log b\n- log(a/b) = log a − log b\n- log(aⁿ) = n · log a"
  }
}
```

- **`outline`** — то, что ученик видит до начала урока («1. Интро, 2. Тема, 3. Задание»).
  Допустимые `kind`: `intro`, `theory`, `practice`, `summary`, `video`, `reading`, `quiz`.
- **`body_md`** — сам текст. Переносы строк записываются как `\n` внутри JSON-строки.

Материал должен быть хотя бы у тех тем, которые вы хотите видеть в дорожной карте:
ИИ подбирает в план только темы, обеспеченные материалом.

## Пробник экзамена

`questions/mock-ent.json` и `mock-nis.json`. Вопросы описываются точно так же,
как в диагностике, но лежат в отдельном пуле — это нужно, чтобы вопрос из пробника
не попал ученику заранее в диагностику.

Блок `mock` описывает сам пробник:

```json
"mock": {
  "code": "mock.ent.math_physics",
  "title": "Пробник ЕНТ — математика и физика",
  "grade": 11,
  "time_limit_sec": 3600,
  "outline": [
    { "step": 1, "kind": "intro", "title": "История Казахстана", "duration_min": null }
  ]
}
```

Сумму баллов считать не нужно — она берётся из вопросов.

Пробники проверяются **полностью автоматически**, по эталонным ответам. ИИ их
не генерирует и не редактирует; он только разбирает результат и подбирает темы
для подготовки.

## Экзамен и олимпиада

`exams.json`. Чтобы завести свою олимпиаду, скопируйте блок `olympiad_generic`
и поменяйте:

```json
{
  "code": "olympiad_math_regional",
  "title_ru": "Областная олимпиада по математике",
  "scale_kind": "points",
  "max_score": 60,
  "profile_slot_count": 1,
  "is_active": true,
  "sections": [
    { "slot_kind": "profile", "slot_index": 1, "subject_code": null, "max_points": 60, "question_count": null, "guess_floor": 0.05 }
  ],
  "subject_options": [
    { "subject_code": "math", "slot_kind": "profile", "sort_order": 10 }
  ]
}
```

- **`max_score`** обязан равняться сумме `max_points` по секциям — это проверяется.
- **`profile_slot_count`** — сколько предметов выбирает ученик.
- **`subject_code: null`** в секции означает «предмет выбирает ученик».
- **`guess_floor`** — какую долю баллов можно набрать угадыванием. Для теста с выбором
  из пяти вариантов около `0.2`, для олимпиады — почти ноль.

Новая цель появится в онбординге сама. Менять код не нужно.

## Разметка в текстах

Работает ограниченный набор, всё остальное показывается как обычный текст:

| Запись | Результат |
|---|---|
| `# `, `## `, `### ` | заголовки трёх уровней |
| `**текст**` | жирный |
| `*текст*` | курсив |
| `__текст__` | подчёркнутый |
| `~~текст~~` | зачёркнутый |
| `> текст` | выделенный блок |
| `- пункт` | список |

HTML не поддерживается: теги будут вырезаны. Внутри JSON перенос строки — это `\n`,
а кавычку внутри текста нужно экранировать: `\"`.

---

## Что проверяет загрузчик

- сумма баллов по секциям экзамена равна его `max_score`;
- `topic_code` и `subject_code` существуют;
- у вопроса с выбором есть варианты, а эталон указывает на существующий вариант;
- у `mcq_single` ровно один верный ответ;
- у `free_text` заполнено `rubric_md`;
- `grade_min` не больше `grade_max`;
- длины текстов в допустимых пределах.

Ошибка называет файл и путь до поля. Например:

```
Файл questions/diagnostic.json не прошёл проверку:
  - questions.7.answer_key: эталонный ответ "f" не найден среди вариантов
```

## Как удалить запись

Удаление из файла запись из базы **не убирает** — загрузчик только добавляет и обновляет.
Это сделано намеренно: случайно удалённая строка не должна уносить с собой попытки учеников,
которые на неё ссылаются.

Чтобы убрать по-настоящему, скажите мне, что удалить, — я подготовлю миграцию.
Для вопросов есть щадящий путь: пометить неактивным, тогда он перестанет попадать
в новые тесты, а старые попытки останутся целыми.

## Что сейчас заготовка

Файл считается заготовкой, если внутри есть `"placeholder": true`. Их список печатается
после каждого `npm run content`.

| Заготовка | Когда понадобится заменить |
|---|---|
| `questions/diagnostic.json` | **перед фазой 4** — от этих вопросов зависит стартовая оценка знаний |
| `lessons.json` | перед фазой 7 — дорожная карта и уроки |
| `questions/mock-ent.json`, `mock-nis.json` | перед фазой 9 — пробники |
| `topics/*.json` для восьми предметов | когда эти предметы должны стать доступными для выбора |

Темы математики, физики, истории Казахстана, грамотности чтения и математической
грамотности заготовками не являются — их можно уточнять, но работать они будут и так.
